# Candidate device records (reviewable, not canonical)

This directory holds **datasheet transcriptions** and the **candidate records** built
from them. Nothing here is canonical evidence: `data/canonical/` remains the only
official corpus, and candidate `device_id`s carry the `candidate_` prefix so that they
can never be mistaken for canonical keys.

| Path | Meaning |
| --- | --- |
| `sic-dab-shortlist-2026-10-21.yaml` | Structured transcription (`aipe-datasheet-transcription/0.1`) of the 10 kW DAB SiC shortlist researched on 2026-10-21 from manufacturer datasheets, plus the two TI reference-design parts as cited by TI. |
| `records/<candidate_id>.json` | Schema 3.0.0 device record generated by `aipe_devices.importers.datasheet` (`python scripts/generate_candidates.py`). `quality.review_status` is `unreviewed`. |
| `records/<candidate_id>.dossier.json` | Review context that has no place in the device schema: datasheet URL/revision/date, product page, model availability and licence notes, field basis, absent quantities, transcription notes, canonical link. |
| `records/index.json` | Overview of the generated candidates. |

Rules applied by the transcription and the importer:

- Values are transcribed **as printed**; units are converted to SI by the explicit
  registry (`mOhm`, `uJ`, `nC`, `pF`, `degC`, `degC/W`, ...). No value is estimated,
  scaled or filled in. Missing quantities are listed under `absent` and become
  `absent:<quantity>` quality flags on the record.
- Each record carries `manufacturer_datasheet` origin and a source with the datasheet
  URL; values that only exist on a product page or in a third-party document (TI
  design guide) are flagged `basis:product_page` / `basis:third_party_cited`.
- Reverse-conduction points use the canonical third-quadrant convention (negative
  drain current, negative voltage drop); the printed positive values stay in the
  record's `source_locators`.
- When a canonical record exists for the same manufacturer/part (Wolfspeed
  C3M0040120K, C4MS047120K, C3M0025065K, CBB021M12FM3, C3M0075120K, C3M0030090K), the
  candidate gets an `AIPE` source with the canonical record URN and the dossier lists
  what the canonical record provides (PLECS tensors, Cauer network). The two records
  are never merged; screening combines them explicitly and reports which evidence
  came from where.
- No datasheet PDF or vendor model file is stored here. Model availability and licence
  notes are catalogue metadata (`models[].adapter_metadata`), not model content.

Promotion to `data/canonical/` requires an engineering review of the transcription
against the PDF, rights confirmation per manufacturer, and a separate import.
